# JuiceGao 个人记录网站

可部署在自己的服务器上。文章、站点资料和上传图片在自己的 Docker 数据卷中保存；后台使用独立的管理员账号与密码。

## 功能

- 首页参考 [Axi-Theme](https://github.com/Axi404/Axi-Theme) 的个人资料与分节布局，展示个人介绍、教育经历卡片、履历卡片、站点统计和写作日历。教育经历与履历可在后台逐条维护、排序，空模块自动隐藏。
- 首页、博客、文章、关于、地图及标签页共用顶部背景图，带渐变遮罩，随页面自然滚出。可在「后台 → 网站资料 → 页面展示」上传、更换或移除，原有背景无需重传，留空时显示柔和渐变底色；后台沿用独立界面。日间模式使用轻微米白底色。首页头像及个人资料通过浏览器原生滚动动画轻移、缩放与渐隐，返回顶部时恢复，不支持时静态显示。
- GitHub、小红书、B站、抖音与邮箱以图标展示，悬停或键盘聚焦显示名称；在「后台 → 网站资料 → 联系方式」维护主页链接，留空的平台不显示。已填入站主的 GitHub（GGGxsb）、小红书、B站主页，抖音默认隐藏；首页个人资料整体位于内容区偏左约三分之一处。
- 文章、分类、标签和搜索均支持数据库分页；前台列表每页 15 条，后台每页 10 条。统计覆盖全部内容，公开页面不会计入草稿。
- Markdown 编辑与预览、草稿发布、图片上传、站点资料和独立账号管理。
- 关于页支持 Axi-Theme 风格的 Sponsor：微信、支付宝二维码默认模糊并显示支付图标，悬停、键盘聚焦或手机点击后显示完整二维码。在「后台 → 网站资料 → 赞助二维码」分别上传自己的图片并保存；未填写的方式自动隐藏。二维码图片在深浅色模式下保留原色与白底。
- 访客填写昵称即可评论和回复，评论审核通过后公开；后台支持搜索、分页、通过、拒绝、删除与站主公开回复。评论以纯文本展示。
- 文章支持点赞与取消点赞，同一 IP 对同一篇文章只计一票；评论每 IP 每 10 分钟最多 5 次，点赞操作每 IP 每 10 分钟最多 30 次。
- 阅读页提供跟随当前章节的目录、阅读进度、返回顶部、手机目录和图片放大；阅读进度按正文计算，不包含评论区。
- Markdown 支持表格、任务列表、删除线、脚注、嵌套列表、KaTeX 数学公式，以及 Shiki 代码高亮和复制；后台预览与前台使用相同渲染器。
- 博客与后台统一使用 Daily Life、Technical 两个固定分类。标签在每篇文章的编辑器里维护，显示于文章列表及文末，点击后精确筛选；首页与博客下拉菜单不再放独立标签入口。支持同分类、同类型文章的上一篇／下一篇导航。公开标签及相邻文章只包含已发布内容。
- 每篇公开文章提供独立的搜索标题、摘要、规范链接、Open Graph/Twitter 分享信息与结构化数据；无封面时使用站点分享图。自动生成站点地图和 robots.txt，后台不参与索引。
- 正文支持提示框、折叠、标签页、步骤、图片组和 GitHub 仓库卡片；后台「插入组件」可直接加入模板，详见 [正文组件写作说明](docs/article-components.md)。
- 按 Axi-Theme 源码适配点击彩色粒子、滚动收窄与显隐导航、300ms 分段入场、卡片箭头形变及封面光晕。为减少滚动开销，导航使用实色背景，只在状态改变时更新；入场扫描仅在前台页面切换时执行，背景与光晕不再逐帧写样式。博客列表封面固定在右侧并向左渐隐，悬停或键盘聚焦时卡片平滑增高以展示完整图片；手机直接使用完整图片所需的高度。封面只在宽度变化时重新计算尺寸，忽略展开动画的高度变化。地图列表沿用独立封面区域的展开效果；教育与履历继续使用原有方向渐隐。沿用已有封面，无需重传。系统启用「减少动态效果」时关闭非必要动效。具体来源及适配说明见 [Axi-Theme 实现对照](docs/axi-theme-reference.md)。

多人共用同一公网 IP 时会共用点赞状态和频率额度。互动数据库仅保存基于私密配置计算的地址摘要，不保存原始 IP；评论不要求邮箱。Docker 自带代理会覆盖访客地址头，应用端口仅在容器内部使用。

## 部署到自己的服务器

以下 Docker 命令在服务器的 Linux 终端中执行。文档中的 `YOUR_SERVER_IP`、`YOUR_SSH_USER` 需要替换为你自己的服务器 IP 和 SSH 登录用户名。网站和数据均运行在服务器上。服务器需要已安装 Docker Engine 和 Docker Compose 插件，先确认 `docker compose version` 能正常运行。

1. 从 GitHub 下载源码压缩包并解压，把项目源码上传到服务器，例如 `~/juicegao-journal`，进入该目录。上传源码时不要上传本地的 `node_modules`、`.next`、`.env` 或测试数据。

2. 生成一次性初始化链接。此步骤只需要 Docker，不需要在服务器安装 Node.js：

   ```sh
   docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/workspace" -w /workspace node:24-bookworm-slim node scripts/setup-admin.mjs
   ```

   命令会新建 `.env`，并显示形如 `http://localhost:8081/admin#setup=...` 的私人链接。保存这条完整链接，稍后创建管理员账号。已有 `.env` 时脚本会停止，不覆盖原配置。

3. 构建并启动：

   ```sh
   docker compose up -d --build
   docker compose ps
   ```

   首次构建会下载依赖；`app` 显示 healthy、`web` 显示 running 后即可访问。

4. 在腾讯云安全组和服务器防火墙放行 TCP `8080`，保留已有的 SSH 端口规则。页面地址为：

   **<http://YOUR_SERVER_IP:8080>**

   应用的 `3000` 端口只在容器之间使用，不需要放行。

## 首次创建管理员

公网 IP 的 HTTP 地址可以浏览网站；后台提交账号、密码需要 HTTPS，或通过下面的 SSH 隧道访问本机地址。

在自己的电脑上打开终端，执行：

```sh
ssh -N -L 8081:127.0.0.1:8080 YOUR_SSH_USER@YOUR_SERVER_IP
```

将 `YOUR_SSH_USER` 替换成服务器实际使用的登录用户名。如果 SSH 使用了其他端口，加入 `-p 端口号`。保持这个终端开启，然后在电脑浏览器中打开第 2 步生成的 `http://localhost:8081/admin#setup=...` 链接。

创建管理员账号后，初始化链接自动失效。以后仍通过隧道访问 **<http://localhost:8081/admin>**，使用自己的账号和密码登录。接入域名与 HTTPS 后可以直接在域名后台登录，无需隧道。这里的 localhost 只是电脑到服务器的 SSH 转发入口，网站仍部署在服务器上。

## 城市地图

点击地图上没有省市区域的空白处会取消当前选择、清除高亮与提示，并保留缩放和平移视角；拖动不会取消选择。清除后的状态会在当前标签页保留，刷新时不会重新选中原城市。

显示市级区域时，省界以独立线层覆盖在城市上方，使用比市界更明显的颜色和固定屏幕线宽，在缩小地图、切换深浅色主题时仍保持清楚，并可正常点击城市。

从全国视角放大到 3 倍时显示市级区域，缩回 2.5 倍时恢复省级；两档门槛之间保留当前层级，避免临界位置反复切换。

导航中的「地图」进入 `/map`，可以点击或搜索城市，查看对应的已发布文章。全国视角显示省份，滚轮放大后按可见省份加载市级边界，并平滑切换；直接滚轮即可缩放，拖动移动视角。点击省份会聚焦并展示该省文章，点击城市查看城市文章。支持手机端文章列表，阅读后点击「返回地图」会恢复选择和视角。

编辑文章时，在「关联城市」搜索并选择一个或多个城市。保存草稿不会公开，发布后才会点亮城市；自动备份和恢复同样保留城市选择。未关联城市的文章仍正常显示在博客中。

更新启动时会自动执行新增城市字段的迁移，保留已有文章、资料、账号、评论和点赞。地图数据已包含在项目中，不需要第三方地图 API key；来源和许可见 [地图数据说明](docs/map-data.md)。

## 发布内容

在 `/admin` 中发布、编辑或删除文章，上传图片，并修改网站资料。草稿仅在后台显示，发布后出现在前台。个人资料和正文由你自己填写。

文章地址统一为 `/posts/记录ID`。ID 由服务端创建并保存为 SQLite `posts` 表的 `id` 主键，修改标题不会改变地址；后台无需填写链接别名。

「博客」下拉菜单只包含 Daily Life 和 Technical，选择后进入对应分类。后台分类同样只能选择这两项，默认 Daily Life；标签在单篇文章的编辑器中填写，多项用逗号分隔。文章列表及文末的标签可精确浏览同一主题。

升级后会自动执行分类迁移：明确的技术分类（Technical/Technology/Tech、技术、技术文章、技术分享、技术笔记、编程、开发）归入 Technical，其余归入 Daily Life；旧分类名会保留为该篇文章的标签，原有标签、文章 ID、内容和互动数据保留。迁移前仍建议按下文备份数据。新写入和更新也由数据库与接口限制为这两个分类。

文章的上一篇／下一篇在同分类的已发布文章之间按发布时间导航，草稿不会出现在公开导航中。

Markdown 表格、任务列表和删除线采用 GFM 语法；行内公式使用 `$...$`，独立公式使用 `$$...$$`。代码围栏后填写语言名称即可高亮，不支持的语言保留原始代码。源 HTML 不会作为可执行页面内容渲染。

搜索与分享使用文章标题、摘要和封面；摘要留空时从正文提取。对外部署时将 `.env` 的 `APP_ORIGIN` 配置为真实网站地址，使分享地址和站点地图使用正确域名。文章更新后元数据随页面重新生成；搜索引擎的展示与收录时间由其抓取决定。

在后台「网站资料」填写个人介绍、上传头像和设置建站日期。教育经历支持学校/机构、学位/专业、时间、说明与可选 HTTPS 链接；履历支持公司/组织、职位/角色、时间、说明与可选链接。两组均可新增、移除与上移/下移，每组最多 20 条，按后台顺序在首页及关于页展示；说明支持 Markdown。原有学习经历文字保留为「教育经历补充说明」，也会继续展示。

写作日历按北京时间统计公开文章的首次发布日期，不计草稿，也不从 GitHub 拉取贡献数据；点击日期可查看当天发布数量。运行天数使用填写的建站日期，留空时从第一篇公开记录算起；尚无起始日期或公开记录时显示「—」。

首页支持切换「写作记录 / GitHub 贡献」。贡献格通过 GitHub 官方 GraphQL API 获取，配置 `GITHUB_CONTRIBUTIONS_TOKEN` 后启用；用户名默认来自网站资料中的 GitHub 主页，也可用 `GITHUB_CONTRIBUTIONS_USERNAME` 指定。数据在 SQLite 中缓存一小时，失败时保留上次成功结果；不要求访客登录。配置步骤见 [GitHub 贡献格](docs/github-contributions.md)。

## 更新与日常操作

更新前请先按下文备份数据。上传新的源码后，在服务器项目目录执行：

```sh
docker compose up -d --build
```

此次评论与点赞更新会在容器启动时自动追加数据库表，保留已有文章和账号，无需重新运行管理员初始化。保留原 `.env` 和数据卷；不要修改已应用的旧迁移文件。

首页更新会自动追加教育经历和履历条目的存储字段，已有资料、学习经历文字和文章保持不变；更新后可直接在后台填写新条目。省略新字段的旧客户端保存资料时，不会清空已经填写的教育经历或履历。

随记和归档功能已移除。启动时自动执行 `0011_remove_post_kinds.sql`，移除文章的类型字段及自动备份中的旧类型设置；原有随记统一作为文章展示，保留 ID、正文、封面、分类、标签、发布状态、评论和点赞。旧 `/notes`、`/archive` 地址跳转到博客列表，筛选参数会保留；本机旧备份仍可恢复。

合集功能已移除。启动时自动执行 `0009_remove_collections.sql`，删除合集表、文章的合集字段和备份中的旧合集设置；文章 ID、正文、封面、分类、标签、评论、点赞及草稿内容保持不变。旧合集页面地址会跳转至博客列表，旧合集管理接口不再提供。浏览器中已有的写作备份仍可恢复，无需重新初始化管理员。

数据库和上传图片保存在名为 `juicegao_data` 的 Docker 数据卷中，重建镜像、重启容器不会清空它们。`.env` 中的 `JOURNAL_DATA_VOLUME` 可指定其他卷名。

```sh
docker compose logs --tail=100 app web
docker compose restart
docker compose down
```

上面依次为查看日志、重启和停止网站。需要再次启动时执行 `docker compose up -d`。保留项目的 `.env` 文件及数据卷。

## 备份

备份包含文章、账号、会话、站点配置和上传图片。先短暂停止写入，备份后恢复运行：

```sh
mkdir -p backups
chmod 700 backups
backup_name="journal-$(date +%Y%m%d-%H%M%S).tar.gz"
docker compose stop app
docker run --rm -v juicegao_data:/data:ro -v "$PWD/backups:/backup" alpine:3.22 tar -czf "/backup/$backup_name" -C /data .
docker compose start app
```

如果设置了自定义数据卷名，将命令中的 `juicegao_data` 替换为实际名称。确认备份命令成功，并将备份文件复制到服务器以外的设备。`.env` 单独妥善备份。

## 恢复备份

恢复到一个新卷，保留原来的卷以便回退。把 `备份文件.tar.gz` 替换为 `backups` 中实际存在的文件名：

```sh
docker compose stop app
restore_volume="juicegao_restore_$(date +%Y%m%d_%H%M%S)"
docker volume create "$restore_volume"
docker run --rm -v "$restore_volume:/data" -v "$PWD/backups:/backup:ro" alpine:3.22 sh -c 'tar -xzf "/backup/备份文件.tar.gz" -C /data && chown -R 1001:1001 /data'
printf '%s\n' "$restore_volume"
```

仅在解压命令成功后，把 `.env` 中 `JOURNAL_DATA_VOLUME` 改为最后显示的新卷名，再执行 `docker compose up -d`。确认内容和登录正常后再自行决定何时清理旧备份与旧卷。

## 使用已有证书启用 Nginx HTTPS

网站默认由 Docker 内的 Nginx 反向代理 Next.js。已有证书时可以继续使用 Nginx，通过 `deploy/compose.nginx-https.yaml` 开启 HTTPS，无需在宿主机另装 Nginx。

1. 在 DNS 中将实际使用域名的 A 记录指向服务器，若配置了 AAAA 记录，也应指向本机可用的 IPv6。安全组与系统防火墙放行 TCP `80` 和 `443`；确认这两个端口未被其他站点占用。
2. 先备份数据，在服务器项目目录拉取最新代码，创建证书目录：

   ```sh
   git pull --ff-only
   mkdir -p deploy/certs
   ```

   将证书平台下载的 Nginx 格式文件（PEM 编码）上传为：

   ```text
   deploy/certs/fullchain.pem  # 站点证书及中间证书链
   deploy/certs/privkey.pem   # 对应的私钥
   ```

   `fullchain.pem` 中站点证书应位于中间证书之前；若平台提供的是 `.crt` 或 `.key` 文件，确认是 PEM 编码后按上述名称保存。`certs/` 已从 Git 与镜像构建中排除，证书只读挂载到 Nginx 容器。
3. 编辑原 `.env`，保留初始化散列和数据卷配置，只设置或更新以下两项。示例域名需要替换成证书覆盖的真实域名：

   ```dotenv
   APP_ORIGIN=https://example.com
   SITE_DOMAIN=example.com
   ```

4. 限制私钥读取权限，构建应用并检查 Nginx 配置。以下操作不会先停止现有网站：

   ```sh
   sudo chmod 600 deploy/certs/privkey.pem
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml build app
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml run --rm --no-deps web nginx -t
   ```

   只有显示配置检查成功后，才继续切换：

   ```sh
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml up -d
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml ps
   ```

   配置沿用原项目名称、服务和数据卷，Compose 会更新现有容器。之后通过 `https://你的域名` 访问网站，`https://你的域名/admin` 登录后台，无需 SSH 隧道。HTTP `80` 会跳转到 HTTPS，原默认 `8080` 入口不再由此配置发布。

5. 后续更新、日志与重启都使用同一配置前缀，例如：

   ```sh
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml logs --tail=100 app web
   ```

   此方案使用你已有的证书，不负责自动续期。续期后替换目录里的两个文件，再检查并重载：

   ```sh
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml exec web nginx -t
   sudo docker compose --env-file .env -f deploy/compose.nginx-https.yaml exec web nginx -s reload
   ```

## 有域名后启用自动 HTTPS（Caddy）

提供了一个独立的 Caddy 部署配置，自动申请和续期域名证书。先将域名的 A 记录指向 `YOUR_SERVER_IP`，确保服务器的 `80`、`443` 端口未被其他服务占用，并在安全组及防火墙放行 TCP `80`、TCP `443`。若已有网站占用这两个端口，请继续使用前面的 IP 与 SSH 隧道方案，不要直接启动本节配置。

在 `.env` 中填写自己的真实域名，例如：

```dotenv
APP_ORIGIN=https://example.com
SITE_DOMAIN=example.com
```

停止默认 HTTP 部署，再启用 HTTPS 配置。数据卷名称保持一致：

```sh
docker compose down
docker compose --env-file .env -f deploy/compose.https.yaml up -d --build
```

此后访问 `https://你的域名` 和 `https://你的域名/admin`。HTTPS 模式的后续更新、查看日志、备份前停止与备份后启动，都使用 `docker compose --env-file .env -f deploy/compose.https.yaml` 作为命令前缀。证书保存在 `juicegao_caddy_data` 卷中。

若一开始就使用域名，可以在生成配置时执行下面的命令，让初始化链接直接使用域名：

```sh
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/workspace" -w /workspace node:24-bookworm-slim node scripts/setup-admin.mjs --app-origin https://你的域名
```

生成后再向 `.env` 添加 `SITE_DOMAIN=你的域名`，然后使用 HTTPS 配置启动。

## 组成

- Next.js 服务端渲染，文章支持 Markdown。
- Node.js 内置 SQLite；数据库和图片保存在同一个数据卷中。
- 独立管理员账号、密码散列、服务端会话及一次性初始化凭据。
- 默认 Nginx 入口 `8080`；可选 Caddy 域名 HTTPS 入口。

## 封面配色与自动备份

文章列表会从封面图片提取主色，悬停或键盘聚焦时联动卡片背景、标题和标签。深浅色模式沿用各自的文字底色；图片无法读取颜色时使用站点默认配色。跨域图片仍正常显示，并使用默认配色；推荐使用后台上传的本站图片以启用自动取色。

教育经历和履历也支持相同的封面渐隐与主色效果：在后台「网站资料」展开对应条目，上传卡片封面或填写图片地址，最后点击「保存资料」。桌面封面从右向左渐隐，手机从上向下渐隐；可更换或移除图片，未设置图片时维持文字卡片。图片地址随条目保存在现有 SQL 资料字段中，原有条目无需迁移，旧编辑器遗漏图片字段时会保留已设置的图片。

后台编辑内容时，修改会先备份到当前浏览器，停笔约 1.2 秒后同步到 SQL 的 `writing_drafts` 表。备份按管理员和文章 ID 保存；尚未手动保存的新内容使用一个独立的 `new` 位置。刷新、重新登录或更换设备后，可从内容管理的“继续未完成的写作”打开服务器备份；断网时可恢复原浏览器中的本机备份。恢复提示允许选择本机版本、服务器版本，或丢弃备份并保留原文。

“继续未完成的写作”中的每个条目都可单独删除：未保存的新内容显示“删除草稿”，已有文章的未发布修改显示“删除备份”，仅移除本机和服务器备份，原文章保留。删除前会确认；若其他窗口已产生更新版本，会保留新内容并提示刷新列表。内容列表及编辑页中的已保存草稿也有“删除草稿”入口，删除原草稿时一并清理其自动备份。

自动备份不会创建公开文章，也不会更新已发布的正文。确认修改后仍需点击“保存草稿”或“更新发布”；成功后清除对应备份。多窗口编辑采用版本检查，旧窗口无法直接覆盖较新备份。备份保存在原数据卷，升级时自动创建新表，无需手动改库；删除原文章时一并删除其服务器备份。本机备份属于当前浏览器，清理站点数据会移除它。

## 阅读量与访问统计

文章列表和正文页显示阅读量，首页统计显示已发布文章的阅读合计和站点总访问量。只有页面在浏览器中实际打开并可见后才会计数；服务端渲染、链接预加载和统计查询本身不会增加计数。已登录后台的站主及常见爬虫不计入。

匿名浏览器使用本站签名的 HttpOnly Cookie 标识，有效期一年；同一标识对同一篇文章只计一次。总访问量按浏览器和页面去重，同一页面 30 分钟内刷新或重复打开只计一次，不同页面分别计数，网址查询参数不另计。清理 Cookie、更换浏览器或设备后会形成新的匿名标识；站主未登录后台时也按访客处理。

升级自动应用 `0013_page_analytics.sql`，在现有 SQLite 数据卷中保存累计值和去重记录，从升级后开始计数。原有文章、评论和写作备份保持原样；阅读量更新不会改变文章的修改时间。去重表只保存匿名散列，不保存原始 IP、访客昵称或浏览器指纹；短期页面去重记录自动清理，累计访问量继续保留。无需第三方统计服务或新增环境变量。

## 评论第三方登录

站主使用同一浏览器登录后台后，文章页会自动识别站主身份。站主直接评论、文章页回复及后台回复均显示盾牌“站主”徽章；前台发言有独立高亮边框，并使用网站资料中的昵称和头像。站主发言直接展示，游客评论仍需审核。身份由服务器验证后台会话确定，同名游客无法获得站主标识。后台登录在新标签页完成后，返回文章页会重新检查身份。

可选 QQ 登录，评论展示平台昵称、头像及身份标识；也可选择游客。所有访客评论继续进入审核，第三方账号没有后台管理权限。QQ 入口仅在服务器配置应用凭据后展示，后台“账号设置”可查看配置状态和回调地址。

申请应用、填写 `juicegao.site` 回调地址及服务器配置步骤见 [评论身份登录](docs/comment-login.md)。新增账号、会话及身份快照会随数据库迁移自动创建；平台密钥留在服务器 `.env`，不提交到仓库。
